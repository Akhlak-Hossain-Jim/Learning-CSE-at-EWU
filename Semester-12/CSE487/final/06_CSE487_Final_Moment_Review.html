Topic 01 · condensed

Blockchain — one page

Definition: \( \text{Blockchain} = DL + CP + C \) — Distributed Ledger + Consensus Protocol + Cryptography.

The 5 pillars (features): Distribution (many copies), Decentralisation (no single controller), Immutability (append-only), Tokenisation (assets on-chain), Encryption/Cryptography. Mnemonic D-D-I-T-E.

Why it exists — the 3 banking failures: central intermediary required; single point of failure; censorship and latency.

The 3 scenarios: Alice pays Bob $5 → decentralisation removes the gatekeeper. Land ownership dispute → immutability removes silent tampering. Charity fund transparency → transparency removes the need to trust a report.

5 layers (top to bottom): Application (dApps, smart contracts) → Data (blocks, Merkle trees, signatures) → Consensus (PoW, PoS, DPoS, PBFT, PoET, PoAh, Raft) → Network (P2P, sharding, DAG) → Execution (EVM, Docker, compilers).

Block anatomy. Header: block number, timestamp, nonce, previous block hash, Merkle root. Body: the transactions.

Merkle root — the faculty's form
\[ H1 = \text{Hash}(T1\|T2), \quad H2 = \text{Hash}(T3\|T4), \quad \text{Merkle Root} = \text{Hash}(H1\|H2) \]

Odd leaf: duplicate it and hash with itself — \(\text{Hash}(T5\|T5)\). Repeat at every level with an odd count.

The tamper cascade (the answer to "how is immutability achieved"): alter a transaction → avalanche effect changes its leaf hash → Merkle root changes → block header changes → block hash changes → the next block's previous-block-hash no longer matches → honest nodes reject it. To hide it the attacker must re-mine every subsequent block faster than the whole honest network — the 51% problem.

Transaction flow (6 steps): request & sign with private key → propagate by gossip → miners assemble a candidate block → consensus (vary the nonce until the hash meets the difficulty target) → append via previous block hash → state settlement.

Digital signatures: sign with the private key, verify with the public key. Proves authenticity and integrity.

Centralised vs decentralised — the six rows: control (single authority / peer nodes), data storage (one server / replicated), message modification (silent / tamper-evident), failure risk (SPOF / fault-tolerant), trust model (entity / protocol), example (WhatsApp, banking / Bitcoin, Ethereum).

Consensus: PoW — miners compete on nonce-hashing; secured by electricity; Bitcoin; high energy cost. PoS — validators selected by stake weight; secured by collateral at risk; Ethereum; low energy, influence tracks wealth. PBFT survives lying (Byzantine) nodes; Raft survives only crashes.

Categories: Public = permissionless, anyone (Ethereum, Polygon, Solana). Private = one organisation (Hyperledger Fabric, Quorum). Consortium = a known group (Corda) — the answer for multi-bank or inter-institutional scenarios.

The trap

Merkle root ≠ previous block hash. Merkle root secures transactions inside one block, downwards. Previous block hash links blocks to each other, backwards. Both live in the header.

Topic 02 · condensed

SOC — one page

Definition: a centralised organisational unit and facility responsible for continuously monitoring, detecting, analysing and responding to cybersecurity threats across an enterprise infrastructure.

6 core functions: prevention & proactive monitoring · alert management & triage · incident response · log management · security intelligence & threat hunting · security posture refinement.

3 pillars: People (Tier 1/2/3, SOC Manager, IR Coordinator → reports to CISO) · Process (SOPs = general workflows; playbooks = attack-specific steps) · Technology (SIEM, SOAR, EDR/XDR, TIP).

Tier ladder — the question each answers: Tier 1 "is it real?" (triage, false-positive filtering, escalate) → Tier 2 "what happened, how far, contain it" (deep-dive, scope analysis, isolation, ACL blocks) → Tier 3 "what did we miss?" (proactive hunting, APTs, reverse engineering, VA/PT, rule refinement) → Manager "how are we performing?" (metrics, staffing, CISO reporting).

SIEM vs SOAR: SIEM detects (aggregates and correlates logs into alerts — Splunk, QRadar, Wazuh). SOAR acts (automated playbooks execute containment).

EDR vs XDR: EDR = endpoints only, host telemetry, device-level visibility, isolate/kill process. XDR = endpoints + network + cloud + identity + email, cross-telemetry correlation, multi-stage attack chains, multi-vector response.

7-phase incident response lifecycle: Alert → Triage → Investigation → Containment → Eradication → Recovery → Reporting & continuous improvement. Order is examinable: stop the bleeding, remove the cause, then restore.

4 types of threat intelligence: Strategic (trends, business impact → CISO, board) · Tactical (IoCs, signatures → Tier 1/2, automated blocking) · Operational (campaigns, motivations, TTPs → incident responders) · Technical (artefacts, malware tooling, exploits → researchers, Tier 3).

Pyramid of Pain (bottom = easy for attacker to change, top = hard): hash values → IP addresses → domain names → network/host artefacts → tools (Mimikatz, Cobalt Strike) → TTPs. MITRE ATT&CK formalises the top: tactics = goal, techniques = method, procedures = the exact observed implementation.

STIX vs TAXII: STIX = the language; TAXII = the taxi that carries it over HTTPS.

4 correlation rules: botnet (firewall/IDS/DNS/proxy → outbound to known C2 → auto-block) · virus outbreak (EDR → ≥3 endpoints in 10 min → isolate) · SQL injection (WAF/web logs → ≥5 signatures → block IP, alert Tier 2) · brute force (AD/VPN → multiple failures followed by a success → lock account, MFA step-up).

3 challenges: alert fatigue · skills shortage (Tier 2/3) · high infrastructure cost (licensing, multi-TB log retention).

The trap

Precision is about the alerts you raised; recall is about the attacks that existed. Recall matters more to a SOC — a false positive wastes an hour, a false negative is a live breach nobody sees.

Topic 03 · condensed

VAPT — one page

Definition: an end-to-end evaluation of an organisation's defensive posture combining automated vulnerability discovery with simulated adversarial exploitation.

The two questions: VA asks "what is weak or unpatched?" · PT asks "can these weaknesses be exploited to gain deep access?"

The one axis: VA = broad, shallow, non-intrusive, automated, continuous, cheap → produces a vulnerability checklist → baseline hygiene and compliance. PT = narrow, deep, intrusive, automated plus manual, periodic, expensive → produces a remediation report based on demonstrated exploits → proof of exploitability and defence readiness.

The sentence that answers most VAPT questions

VA measures exposure. PT measures risk. VA gives breadth without proof; PT gives proof without breadth. Together they turn a long unprioritised list into a short evidence-backed one.

What VA cannot do: prove exploitability · chain several findings into an attack path · assess business impact · test whether the SOC would notice · avoid false positives. What PT cannot do: cover the estate · run continuously (it is a snapshot that ages) · scale affordably.

5 scan types: network-based (ports, unencrypted services, weak ACLs) · host-based (OS config, missing patches, registry) · wireless (rogue APs, WEP/WPA) · application (SQLi, XSS, CSRF, APIs) · database (accounts, default credentials, weak SQL).

Host discovery: ARP for the local subnet, ICMP echo for wider ranges.

SAST vs DAST: Static = still — scans source code not running (white-box in character). Dynamic = running — scans a live application in real time (black-box in character).

7-stage PT methodology: 1 Pre-engagement (rules of engagement, scope, windows, legal authorisation) → 2 Reconnaissance (OSINT: DNS, mail headers, infrastructure) → 3 Scanning & enumeration (Nmap, banner grabbing) → 4 Gaining access (SQLi, buffer overflow, session hijacking, password cracking) → 5 Maintaining access (reverse shells, scheduled jobs, backdoors, C2) → 6 Covering tracks (testing whether logging caught it) → 7 Reporting (PoC, business impact, remediation).

3 approaches: black box = zero knowledge (external attacker, most realistic, slowest) · gray box = partial, low-privilege credentials or diagrams (insider or post-foothold, best value) · white box = full source and architecture (most coverage, least realistic).

Tools by stage: discovery — Nmap · vulnerability assessment — Nessus, OpenVAS, Nikto · web app testing — Burp Suite, OWASP ZAP · packet analysis — Wireshark. Free equivalents: Nessus→OpenVAS, Burp→ZAP.

OWASP smart contract 2026 changes: SC01 Access Control and SC06 Unchecked External Calls unchanged. NEW: Arithmetic Errors (SC07), Proxy & Upgradeability (SC10). REMOVED: Insecure Randomness, DoS. Elevated under new names: Business Logic (SC02), Flash Loan-Facilitated Attacks (SC04).

5 benefits: safeguard user data · real-time risk visibility from demonstrated exploit paths · regulatory compliance (ISO 27001, PCI-DSS, HIPAA) · strengthen incident response by testing the blue team · optimise security budgets with data-backed metrics.

The trap

Stage 6 is not the tester hiding. Covering tracks measures whether the SOC's logging captured the intrusion and whether an attacker could purge the evidence. And stage 1 is not optional paperwork — without written authorisation the same acts are offences under Sections 18 and 32.

Topic 04 · condensed

Risk Management — one page

5 pillars of Information Assurance: Confidentiality · Integrity · Availability · Authentication (are you who you claim — before) · Non-repudiation (you cannot deny it — after).

The four concepts: Asset = valuable hardware, software, data or personnel. Threat = a potential event capable of causing harm (external, you cannot remove it). Vulnerability = a flaw or misconfiguration in your defences (you can). Risk = the net negative consequence when a threat exploits a vulnerability.

The governing equation
\[ \text{Risk} = \text{Likelihood} \times \text{Impact} \]

Matrix values: likelihood High 1.0 / Medium 0.5 / Low 0.1; impact High 100 / Moderate 50 / Low 10. Bands: Low 1–10, Medium >10–50, High >50–100. (Exactly 10 is Low; exactly 50 is Medium.)

Lifecycle: Establish context → Risk identification → Risk analysis (produces numbers) → Risk evaluation (produces decisions) → Risk treatment, with communication & consultation and monitoring & critical review running alongside all five.

6 treatment responses: Avoid (remove the asset or function — the only route to zero) · Mitigate (controls to cut likelihood or impact) · Transfer (insurance, outsourcing — moves money only) · Accept (when mitigation costs more than the loss — a documented decision) · Contingency plan (DR and IR playbooks — reduces impact) · Management action (process change, training, restructuring).

Choosing one: essential function? no → Avoid. Mitigation < ALE? yes → Mitigate. Purely financial and insurable? → Transfer. Mitigation > loss? → Accept. Add a contingency plan alongside whatever you chose.

Banking asset inventory: core software (CBS, switching engine — High) · applications (DMS, HR, portals) · databases (CBS DB, credentials, source code — High) · human resources (C-suite, IT ops, end-users — phishing susceptibility as a vulnerability).

Classroom assessment columns: asset · vulnerability · risk · impact · likelihood · priority (= Impact × Likelihood) · control · motivation · attack type. Highest-rated: USB drives (Critical), Wi-Fi router and student PCs/laptops (Very High).

4 case studies — root causes: WannaCry (May 2017, EternalBlue/ SMBv1, 200k systems/150 countries, NHS; kill switch; root cause = unpatched end-of-life Windows) · Yahoo (2013–14, disclosed 2016, 3 billion accounts, $350m price cut; weak controls, outdated hashing, undetected APT) · Equifax (July 2017, Apache Struts CVE-2017-5638, 147m consumers, CEO/CIO/CISO resigned; failed patch management) · Colonial Pipeline (May 2021, DarkSide, $4.4m ransom / $2.3m recovered; leaked VPN credentials without MFA).

Business case model: Issue → Root cause → Solution → Effect. Roadmap: short-term MFA + critical patches + awareness; medium-term SIEM/SOC + policy + audits; long-term zero-trust + culture. Inaction costs 5×–10× proactive defence.

Frameworks: ISO 27001 = ISMS, certifiable. SOC 2 = attestation report from a CPA firm, not a certification. NIST CSF = Identify/Protect/Detect/Respond/Recover, self-assessed. PCI DSS = card data, QSA or SAQ. CIS = 18 prioritised controls.

The trap

Insurance does not remove the risk. Transfer moves financial liability — not reputation, not regulatory sanction, and not the due-diligence obligation.

Topic 05 · condensed

Cyber Law — one page

Definition: the comprehensive legal framework governing internet operations, digital telecommunications, computing hardware, electronic data privacy and online transactions.

6 domains: cybercrime · data privacy (GDPR, cross-border flows) · intellectual property (copyright, piracy, patents) · electronic commerce (smart contracts, digital signatures, consumer rights) · national security (critical infrastructure, cyber terrorism) · freedom of speech (the only balancing domain — expression versus defamation).

5 cybercrime categories: DDoS & botnets · identity theft & social engineering · cyberstalking & harassment · PUPs & malware · software piracy.

Cyber insurance covers: direct financial loss (phishing, invoice redirection, spoofing) · fraudulent transactions · system restoration · extortion losses and forensics · legal liability and defence. All of it is money.

The sections — the examinable core

§ Offence Max penalty
18Unauthorised computer accessSimple: 6 months / 200,000 BDT · Malicious or substantial harm: 3 years / 1,000,000 BDT
19Damage to systems, malware infiltration, data corruption, DoS7 years / 11,000,000 BDT
20Source code modification & tampering3 years / 300,000 BDT
22Digital & electronic forgery5 years / 500,000 BDT
27Cyber terrorism & infrastructure sabotage14 years / 10,000,000 BDT
32Hacking — unauthorised deletion, modification, network intrusion14 years / 10,000,000 BDT

Memory patterns: §20 → 3 yrs / 300k and §22 → 5 yrs / 500k (fine = years × 100,000). §27 and §32 are identical twins at the ceiling. §18 is the only two-tier section. §19 has the highest fine at 11,000,000 BDT despite a lower sentence.

The boundary that decides scenarios: got in and only looked → 18 · caused damage, deployed malware, ran a DoS → 19 · intruded and deleted/modified data → 32 · touched source code → 20 · faked a signature or identity → 22 · targeted national security or critical infrastructure → 27. Real incidents engage several — list them all, then name the most serious.

Duty of due diligence — 3 obligations: 1. Preserve forensic evidence (uncorrupted access logs, packet captures, memory dumps). 2. Report promptly to law enforcement and regulators — BGD e-Gov CIRT. 3. Liability persists: organisations maintain legal liability even when victimised; failure to exercise reasonable cybersecurity diligence attracts severe civil regulatory penalties.

Ethics — the don'ts: never use privileged data for private profit · never deploy pirated or unvetted software · never shift blame to colleagues or conceal breaches.

The trap

Wiping the compromised server first destroys the evidence. Preserve before you contain, contain before you eradicate, eradicate before you recover. And a pen tester's authorisation is scope-bound — your client cannot consent on a third party's behalf.

Topic 06

Every formula, in one place

The sheet to read on the exam morning.

Risk management — the quantitative chain

The chain, in order of use
\[ \text{EF} = \frac{\text{Loss Amount}}{\text{Total Asset Value}} \qquad \text{SLE} = \text{AV} \times \text{EF} \qquad \text{ALE} = \text{SLE} \times \text{ARO} \] \[ \text{Risk} = \text{Likelihood} \times \text{Impact} \qquad \text{Net Benefit} = \text{Annual Savings} - \text{TCO} \] \[ \text{ROI} = \frac{\text{Net Benefit}}{\text{TCO}} \times 100 \qquad \text{ROSI} = \frac{\text{Loss Avoided} - \text{Cost}}{\text{Cost}} \times 100 \]

Rules that go with them. ARO may be fractional — once in 10 years = 0.1; 3 events in 4 years = 0.75. Annualise any monthly cost (× 12) before comparing. Match the AV period to the incident period. For a control that reduces rather than eliminates, savings = \(\text{ALE}_{\text{before}} - \text{ALE}_{\text{after}}\).

SOC — time metrics

Means: total time ÷ a count
\[ \text{MTTD} = \frac{\text{Total Detection Time}}{\text{Incidents}} \qquad \text{MTTR}_{\text{resp}} = \frac{\text{Total Response Time}}{\text{Incidents}} \qquad \text{MTTR}_{\text{rec}} = \frac{\text{Total Recovery Time}}{\text{Incidents}} \] \[ \text{MTTA} = \frac{\text{Total Ack. Time}}{\textbf{Alerts}} \qquad \text{MTBF} = \frac{\text{Operating Time}}{\text{Failures}} \qquad \text{MTBI} = \frac{\text{Operating Time}}{\text{Incidents}} \]

SOC — rate and quality metrics

Rates: part ÷ whole × 100
\[ \text{Resolution Rate} = \frac{\text{Resolved}}{\text{Incidents}} \times 100 \qquad \text{Detection Rate} = \frac{\text{Detected}}{\textbf{Actual Threats}} \times 100 \] \[ \text{FPR}_{\text{operational}} = \frac{FP}{\textbf{Total Alerts}} \times 100 \qquad \text{FPR}_{\text{matrix}} = \frac{FP}{FP + TN} \times 100 \] \[ \text{FNR} = \frac{FN}{TP + FN} \times 100 \qquad \text{Recall (TPR)} = \frac{TP}{TP + FN} \times 100 \qquad \text{Precision} = \frac{TP}{TP + FP} \times 100 \] \[ \text{Accuracy} = \frac{TP + TN}{TP+FN+FP+TN} \times 100 \qquad F1 = 2 \times \frac{P \times R}{P + R} \]

Rules. Use the matrix FPR when TN is given, the operational one when only a total alert count is given — and say which you used. Compute F1 from decimals, not percentages. Detection rate + FNR = 100%, always.

SOC — operational metrics

Operational
\[ \text{SLA Compliance} = \frac{\text{Within SLA}}{\text{Incidents}} \times 100 \qquad \text{Escalation Rate} = \frac{\text{Escalated}}{\text{Incidents}} \times 100 \] \[ \text{Analyst Utilisation} = \frac{\text{Time Handling}}{\text{Total Working Time}} \times 100 \qquad \text{Alerts per Analyst} = \frac{\text{Alerts}}{\text{Analysts}} \] \[ \text{Cost per Incident} = \frac{\text{SOC Cost}}{\text{Incidents}} \qquad \text{Containment Rate} = \frac{\text{Contained}}{\textbf{Detected Threats}} \times 100 \] \[ \text{Automation Rate} = \frac{\text{Automated Responses}}{\text{Total Responses}} \times 100 \qquad \text{Log Coverage} = \frac{\text{Systems Sending Logs}}{\textbf{Total Systems}} \times 100 \] \[ \text{Security Incident Rate} = \frac{\text{Incidents}}{\textbf{Total Systems}} \times 100 \qquad \text{Percentage Change} = \frac{\text{old} - \text{new}}{\textbf{old}} \times 100 \]
The denominator map — the single most useful thing here

÷ Incidents: MTTD, MTTR (both), MTBI, resolution rate, SLA compliance, escalation rate, closure rate, cost per incident.
÷ Alerts: MTTA, operational FPR, alert accuracy, alerts per analyst.
÷ Actual attacks: detection rate, FNR, recall.
÷ Detected threats: containment rate.
÷ Total systems: log coverage, security incident rate.
÷ Failures: MTBF. ÷ Analysts: alerts per analyst. ÷ Total responses: automation rate.

Write the denominator down before you touch the calculator. Almost every lost mark in the SOC maths is a wrong denominator, not wrong arithmetic.

Round 1 — Blockchain · 10 questions
  1. Write the faculty's definition of blockchain as an equation.
  2. Name the five pillars.
  3. Give the Merkle root formula for four transactions.
  4. What happens with five transactions?
  5. Which two fields in the block header do the structural work, and what does each do?
  6. Which key signs a transaction, and which verifies it?
  7. Name the five layers, top to bottom.
  8. What is a nonce, and which consensus protocol uses it?
  9. Which blockchain category suits six mutually distrusting banks?
  10. What is the difference between PBFT and Raft?
Show answers

1. \( \text{Blockchain} = DL + CP + C \) — Distributed Ledger + Consensus Protocol + Cryptography.

2. Distribution, Decentralisation, Immutability, Tokenisation, Encryption.

3. \(H1=\text{Hash}(T1\|T2)\), \(H2=\text{Hash}(T3\|T4)\), \(\text{Root}=\text{Hash}(H1\|H2)\).

4. The unpaired leaf is duplicated and hashed with itself — \(\text{Hash}(T5\|T5)\) — and the rule repeats at any level with an odd count.

5. The previous block hash links block \(N\) to \(N-1\), making it a chain and securing history. The Merkle root fingerprints all transactions in the body, making the block's contents tamper-evident.

6. Sign with the private key; verify with the public key.

7. Application, Data, Consensus, Network, Execution.

8. An arbitrary number varied until the block header's hash falls below the difficulty target. Used by Proof of Work.

9. Consortium (Corda, Hyperledger) — shared governance across known members, permissioned so it is not publicly readable.

10. PBFT is Byzantine fault tolerant — it survives nodes that actively lie. Raft is only crash fault tolerant.

Round 2 — SOC theory · 10 questions
  1. Give the definition of a SOC.
  2. Name the three pillars.
  3. What is the difference between an SOP and a playbook?
  4. What question does each analyst tier answer?
  5. Which tier's work starts without an alert?
  6. Difference between SIEM and SOAR?
  7. Name the seven incident response phases in order.
  8. Why must containment precede recovery?
  9. Name the four threat intelligence types and their consumers.
  10. STIX or TAXII — which is the transport protocol?
Show answers

1. A centralised organisational unit and facility responsible for continuously monitoring, detecting, analysing and responding to cybersecurity threats across an enterprise infrastructure.

2. People, Process, Technology.

3. SOPs are general documented workflows — alert handling, escalation matrices, cross-team communication. Playbooks are attack-specific step-by-step responses (phishing, ransomware, brute-force, SQLi).

4. Tier 1: "is it real?" · Tier 2: "what happened and how do we contain it?" · Tier 3: "what have we not detected at all?" · Manager: "how well is the SOC performing?"

5. Tier 3 — proactive threat hunting starts without any alert having fired.

6. SIEM detects: aggregates and correlates logs into alerts. SOAR acts: executes automated response playbooks.

7. Alert, Triage, Investigation, Containment, Eradication, Recovery, Reporting & continuous improvement.

8. Restoring systems from backup while the attacker still holds access simply re-infects them. Stop the spread, remove the cause, then restore.

9. Strategic → CISO/board · Tactical → Tier 1/2 and automated blocking · Operational → incident responders · Technical → researchers and Tier 3.

10. TAXII is the transport (over HTTPS). STIX is the structured language.

Round 3 — SOC maths · 10 questions
  1. MTTD formula, and what denominator?
  2. MTTA uses which denominator, and why is it different?
  3. Detection rate formula.
  4. Precision formula — and in one phrase, what is it about?
  5. Recall formula — and in one phrase, what is it about?
  6. Which matters more to a SOC, and why?
  7. 720 min detection time over 60 incidents — MTTD?
  8. TP=180, FP=20 — precision?
  9. TP=180, FN=20 — recall?
  10. Why is accuracy a misleading metric in security?
Show answers

1. \( \text{MTTD} = \frac{\text{Total Detection Time}}{\text{Number of Incidents}} \) — denominator is incidents.

2. Alerts. Acknowledgement happens to alerts before they are ever classified as incidents.

3. \( \frac{\text{Detected Threats}}{\text{Actual Threats}} \times 100 \).

4. \( \frac{TP}{TP+FP} \times 100 \) — about the alerts you raised: what fraction were real?

5. \( \frac{TP}{TP+FN} \times 100 \) — about the attacks that existed: what fraction did you catch?

6. Recall. A false positive costs an analyst an hour; a false negative is a live breach nobody can see, and the attacker keeps escalating for as long as it goes undetected.

7. \( 720 / 60 = \mathbf{12} \) minutes.

8. \( 180/200 \times 100 = \mathbf{90\%} \).

9. \( 180/200 \times 100 = \mathbf{90\%} \). (Same arithmetic, different meaning — note the denominator changed from FP to FN.)

10. True negatives dominate security data, so a detector that flagged nothing still scores very high accuracy while catching zero attacks.

4. Network-based, host-based, wireless, application, database.

5. SAST — it scans source code in a non-running state.

6. Pre-engagement, Reconnaissance, Scanning & enumeration, Gaining access, Maintaining access, Covering tracks, Reporting.

7. The tester assesses whether the SOC's logging captured the intrusion and whether forensic traces could be modified or purged. It is a test of the defenders, not concealment.

8. Gray box — partial knowledge, simulating a foothold or a malicious insider.

9. Nmap for port scanning; Burp Suite (or OWASP ZAP) for web application proxying.

10. Arithmetic Errors (SC07) and Proxy & Upgradeability Vulnerabilities (SC10). Removed: Insecure Randomness and DoS.

Round 5 — Risk Management & Cyber Law · 10 questions
  1. Write the SLE and ALE formulas.
  2. AV = $80,000/week, EF = 25%, ARO = 5. What is the ALE?
  3. A control costs $9,000/month and removes an ALE of $95,000. Verdict?
  4. An event happens once every 8 years. What is the ARO?
  5. Name the six treatment responses.
  6. What does insurance not transfer?
  7. Which sections carry 14 years and 10,000,000 BDT?
  8. Which section has the highest fine, and what is it?
  9. Someone breaks in, looks around, changes nothing. Which section?
  10. State the three duties on discovering a compromise.
Show answers

1. \( \text{SLE} = \text{AV} \times \text{EF} \) and \( \text{ALE} = \text{SLE} \times \text{ARO} \).

2. \( \text{SLE} = 80{,}000 \times 0.25 = \$20{,}000 \); \( \text{ALE} = 20{,}000 \times 5 = \mathbf{\$100{,}000/\text{year}} \).

3. \( \text{TCO} = 9{,}000 \times 12 = \$108{,}000 \). Net \( = 95{,}000 - 108{,}000 = -\$13{,}000 \). Not justified — Accept the risk (or negotiate a cheaper control). Note the ×12 is the whole question.

4. \( \text{ARO} = 1/8 = \mathbf{0.125} \) per year.

5. Avoid, Mitigate, Transfer, Accept, Contingency plan, Management action.

6. Reputation, regulatory sanction, and the due diligence obligation — an organisation retains legal liability even when victimised. Insurance moves money only.

7. Section 27 (cyber terrorism / infrastructure sabotage) and Section 32 (hacking).

8. Section 19 — up to 11,000,000 BDT, with up to 7 years' imprisonment.

9. Section 18 — unauthorised computer access. Nothing was altered or damaged, so 19 and 32 do not engage. Simple access: 6 months / 200,000 BDT; with malicious intent or substantial harm: 3 years / 1,000,000 BDT.

10. Preserve forensic evidence (logs, packet captures, memory dumps) · report promptly to law enforcement and regulators (BGD e-Gov CIRT) · recognise that liability persists even as a victim, since failure to exercise reasonable diligence attracts civil regulatory penalties.

Topic 09

Exam-day tactics

How to convert what you know into marks.

On maths questions

  1. Write the formula before substituting. If the arithmetic goes wrong you still get method marks; if you only write a number you get nothing.
  2. Write the denominator down first in SOC metric questions. Every question deliberately supplies several candidate denominators.
  3. Annualise everything before comparing. Monthly cost × 12.
  4. Carry the units — minutes, hours, %, BDT, $ — and check them at the end. A "mean time" must come out in time units.
  5. Sanity check. Recovery time > response time. Detection rate + FNR = 100%. F1 lies between precision and recall. EF ≤ 1.0.
  6. State the verdict in words, not just a number. "Net benefit is −$64,000, so the control is not financially justified; the appropriate response is Accept."

On story/analytical questions

  1. Decode the story into the framework first. Spend one minute mapping each event to a stage, phase or section before writing prose.
  2. Name the source. "Under the 7-stage methodology this is stage 5, maintaining access" scores better than a description of what happened.
  3. Answer in the shape the question asks for. "Failure → property → mechanism", "what / when / who / how / root cause", "compare across six criteria" — the wording tells you the structure the marker is using.
  4. List every applicable section or stage, then name the most significant. Do not hunt for a single answer when the facts support several.
  5. Close with the limitation. Almost every top-band answer ends by naming what the analysis leaves out — the unpriced risks, the residual exposure, the fact that blockchain secures the record but not the truth behind it.

Cross-topic links worth making

Examiners reward answers that connect topics, and this syllabus is unusually well-joined. Four links you can deploy almost anywhere:

  • VAPT → Risk Management. A pen test's demonstrated exploit paths supply the likelihood input to \(\text{Risk}=\text{Likelihood}\times\text{Impact}\), and therefore to the ARO in the ALE calculation.
  • VAPT → SOC. Stage 6, covering tracks, is how you find out whether your SIEM correlation rules actually fire — the benefit "strengthen incident response by testing the blue team".
  • VAPT → Cyber Law. Stage 1 pre-engagement authorisation is the only thing separating a penetration test from offences under Sections 18 and 32.
  • Blockchain → Risk Management. Digital signatures deliver the non-repudiation pillar of Information Assurance; hashing delivers integrity.
If you run short of time

Answer in bullets with the key terms bolded rather than abandoning a question. A structured skeleton — the six criteria, the seven stages, the formula and the substitution — collects most of the available marks. An unfinished elegant paragraph collects few.

Master cheat sheet — all five topics

Blockchain =

\( DL + CP + C \). Pillars: Distribution, Decentralisation, Immutability, Tokenisation, Encryption.

Merkle root

\( \text{Hash}\big(\text{Hash}(T1\|T2)\,\|\,\text{Hash}(T3\|T4)\big) \). Odd leaf → hash with itself.

Tamper cascade

tx → leaf hash → Merkle root → header → block hash → next block's prev-hash mismatch → rejected.

Keys

Sign private, verify public. Gives authenticity + integrity + non-repudiation.

Consensus

PoW = compete, secured by electricity. PoS = selected by stake, secured by collateral. PBFT survives liars; Raft only crashes.

SOC =

People + Process + Technology. T1 triage → T2 investigate/contain → T3 hunt → Manager → CISO.

IR order

Alert → Triage → Investigate → Contain → Eradicate → Recover → Report.

Time metrics

\( \text{MTTD}=\frac{\text{det}}{\text{incidents}} \), \( \text{MTTA}=\frac{\text{ack}}{\text{alerts}} \), \( \text{MTBF}=\frac{\text{uptime}}{\text{failures}} \).

P vs R

Precision \( \frac{TP}{TP+FP} \) = alerts raised. Recall \( \frac{TP}{TP+FN} \) = attacks that existed. Recall wins.

F1

\( 2\times\frac{P\times R}{P+R} \), in decimals. Sits between P and R, nearer the smaller.

Denominators

Incidents → MTTD/MTTR/resolution/SLA/cost. Alerts → MTTA/FPR. Actual attacks → detection rate/FNR/recall. Systems → log coverage.

Free checks

Detection rate + FNR = 100%. Recovery > response. EF ≤ 1.0. F1 between P and R.

VAPT line

VA measures exposure. PT measures risk. Breadth without proof vs proof without breadth.

7 PT stages

Pre-engage → Recon → Scan/enum → Gain access → Maintain → Cover tracks → Report.

Box types

Black = zero knowledge. Gray = low-priv creds. White = full source. SAST=still, DAST=running.

THE CHAIN

\( \text{SLE}=\text{AV}\times\text{EF} \) → \( \text{ALE}=\text{SLE}\times\text{ARO} \) → compare vs annualised TCO.

ARO

Can be fractional. 1-in-10-yrs = 0.1. 3 in 4 yrs = 0.75. Monthly cost ×12.

Partial mitigation

Savings = ALEbefore − ALEafter, not the full ALE.

6 responses

Avoid · Mitigate · Transfer · Accept · Contingency · Management action.

Risk matrix

L: 1.0/0.5/0.1 × I: 100/50/10. Low 1–10, Med >10–50, High >50–100.

Case root causes

WannaCry = unpatched EOL Windows. Equifax = unpatched Struts CVE. Colonial = VPN creds, no MFA. Yahoo = weak controls + undetected APT.

§18 / §19

18: access only — 6mo/200k, or 3yr/1M if malicious. 19: damage/malware/DoS — 7yr/11M.

§20 / §22

20: source code — 3yr/300k. 22: forgery — 5yr/500k. (Fine = years × 100,000.)

§27 / §32

Identical twins: 14 years / 10,000,000 BDT. 27 = cyber terrorism/critical infrastructure. 32 = hacking.

Section boundary

Looked only → 18. Damaged → 19. Intruded + deleted/modified → 32. Source code → 20. Forged → 22. National security → 27.

Due diligence

Preserve evidence → report to BGD e-Gov CIRT → liability persists even as a victim.

Biggest IR error

Wiping the server first. Preserve before contain, contain before eradicate.

Formula before substitution. Denominator before calculator. Verdict in words. Close with the limitation.
