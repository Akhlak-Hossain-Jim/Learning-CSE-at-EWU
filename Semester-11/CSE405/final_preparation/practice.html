Distance Vector Routing — Theory

Core idea: Each router knows only the distance (cost) to each destination and which neighbor to use as the next hop. Routers share their entire routing table with direct neighbors periodically.

Bellman-Ford Equation

The foundation of DV routing is the Bellman-Ford algorithm:

Dx(y) = min over all neighbors v { cost(x,v) + Dv(y) }

Where D_x(y) = least-cost path from x to y, cost(x,v) = direct link cost from x to neighbor v, D_v(y) = neighbor v's known cost to y.

How the Algorithm Works

1
Initialize: Each router sets distance to itself = 0, distance to directly connected neighbors = link cost, all others = ∞
2
Share: Each router sends its distance vector (table) to all direct neighbors
3
Update: On receiving a neighbor's table, recalculate using Bellman-Ford. If a shorter path is found, update your own table
4
Repeat: Continue until no table changes occur (convergence)
5
React to change: If a link cost changes, update local table and re-share with neighbors

Table Structure

Each router maintains a table: for every destination, record the best cost and the next hop neighbor.

Destination Cost Next Hop
A (self) 0 —
B 4 B
C 7 B

Example: Router A's table. To reach C, cost is 7 via neighbor B.

RIP — Routing Information Protocol

Distance Vector Protocol
UDP Port 520

Key Characteristics

Metric

Hop count (each router = 1 hop). Maximum 15 hops — 16 = infinity (unreachable). Simple but ignores bandwidth.

Update Behavior

Sends full routing table to neighbors every 30 seconds. Only to directly connected neighbors.

Versions

RIPv1: Classful only, broadcast updates.
RIPv2: Classless (CIDR support), multicast 224.0.0.9, MD5 auth.

Timers

Update: 30s
Invalid/Expire: 180s (no update received)
Flush: 240s (removed from table)

RIP Table Creation — Step by Step

Rules: distance to a directly connected node = 1 hop. When receiving a neighbor's table, add 1 to all their distances.

Topology: A–B–C–D–A (ring). All links = 1 hop.

RIP Limitations

Slow convergence: With 15-hop limit, a failure can take many update cycles to propagate — causes "counting to infinity"

No load balancing: Only one path stored per destination

Metric ignores bandwidth: A 56 Kbps link counts same as 1 Gbps if hop count is equal

Routing Instability Problems

Two-Node Instability (Counting to Infinity)

Scenario: B–X link fails

1
B detects link to X is down → sets D(X) = ∞
2
Before B can advertise this, A sends update: "I can reach X in 2 hops" (A's old table: X via B = 1+1)
3
B thinks: "A says X is 2 hops, so I can reach X via A in 3 hops!" → sets D(X) = 3 via A
4
A gets B's update: "X is 3 hops" → A updates: X = 4 via B. Loop continues...
5
Counts to 16 (infinity) before stopping — very slow convergence!

Root cause: A and B form a routing loop. Each thinks the other has a valid path to X. Neither knows the path was through the failed link.

Solutions to Two-Node Instability

Split Horizon

Do not advertise a route back to the neighbor you learned it from. A will not tell B "I can reach X via B" — because A learned that from B.

Prevents two-node loops completely

Poison Reverse

Instead of silence, actively advertise the route as unreachable (∞) back to the neighbor it was learned from.

More explicit — faster convergence

Triggered Updates

When a route changes, send an update immediately rather than waiting for the 30-second timer. Reduces the window for loops to form.

Three-Node Instability

Why split horizon fails here

1
C–X link fails. C sets D(X) = ∞. Informs B.
2
B also sets D(X) = ∞. Split horizon: B won't tell C "I heard X via C". Correct so far.
3
But B still has A's update: "A says X is 3 hops" (A→B→C→X old route). B thinks X is reachable via A!
4
B advertises to C: "X is 4 hops (via A)". C updates: X = 5 via B. Loop starts again.
5
A, B, C all count to infinity together — split horizon didn't help because the loop involves all 3 nodes.

Key insight: Split horizon only prevents a router from advertising a route back to where it was learned from. It cannot prevent loops spanning 3+ nodes where each router learned the route from a different neighbor.

Solution: Hold-down timers — after a route becomes invalid, ignore updates claiming a better path for a period of time (prevents false "recovery" routes)

OSPF & Link State Routing

Link State Protocol
IP Protocol 89

Core Concept

Every router has a complete map of the network topology. Each router floods its link-state advertisements (LSAs) to all routers. After flooding, every router runs Dijkstra's algorithm independently to compute shortest paths.

Link State vs Distance Vector

DV (RIP) LS (OSPF)
Knowledge Neighbors only Full topology
What's shared Distance table Link costs (LSA)
Algorithm Bellman-Ford Dijkstra
Convergence Slow Fast
Loops Possible None (complete map)

OSPF Features

Authentication: MD5 or plaintext password on updates

Multiple metrics: Bandwidth-based cost (100 Mbps / link bandwidth)

Areas: Hierarchical routing — area 0 = backbone, reduces LSA flooding

Equal-cost multipath: Load balances across equal-cost paths

Dijkstra's Algorithm — Shortest Path Finding

Dijkstra's computes the shortest path from a single source to all other nodes. OSPF runs this locally after receiving all LSAs.

At each step: pick the unvisited node with the smallest known distance, then relax all its neighbors

Steps

1
Set source = 0, all others = ∞. Mark all nodes as unvisited.
2
Pick the unvisited node with smallest distance — call it current node u.
3
For each unvisited neighbor v of u: if dist(u) + cost(u,v) < dist(v), update dist(v) = dist(u) + cost(u,v), and set predecessor of v = u.
4
Mark u as visited. Repeat from step 2 until all nodes visited.
5
Trace back predecessors from any destination to get the shortest path.

Worked Example — Dijkstra's

Source = u. Find shortest paths to all other nodes.

Step Visited u v w x y
Init — 0 ∞ ∞ ∞ ∞
1 {u} — 2 5 ∞ ∞
2 {u,v} — — 5 5 6
3 {u,v,w} — — — 5 6
4 {u,v,w,x} — — — — 6*
Final: u→v=2, u→w=5, u→x=5 (via v), u→y=6 (via w)

*y via w: 5+1=6, also y via x: 5+2=7 — w path wins

Problem 3 — Scenario: Counting to Infinity

InstabilityScenario

Network: Routers A–B–C in a line. A–B cost 1, B–C cost 1. All tables converged. Then link A–B fails.

Questions:

a) What does router B do first when it detects the failure?

b) Trace through the first 3 update cycles. What happens to B's distance to A?

c) How does Split Horizon prevent this loop?

d) Would Split Horizon also prevent instability if a 4th router D were added, with D–C cost 1?

Answers

a) B sets D(A) = ∞ (infinity) and should send an update to C.

b) Before B can update C, C tells B "I can reach A in 2 hops" (C's old table: A via B = 1+1=2). B updates D(A) = 3 via C. B tells C: A = 3. C updates to 4. B updates to 5... counts to 16.

c) With Split Horizon: C learned A via B, so C never tells B "I can reach A." B receives no claims of a path to A, keeps D(A) = ∞. Loop never starts.

d) No. D learned A via C→B, not directly from B. So Split Horizon doesn't stop D from advertising A back to C. The loop now involves B, C, D — three-node instability occurs.

Problem 4 — Theoretical Short Answer

Theory

Q1. Why does OSPF converge faster than RIP after a topology change?

Q2. What is the purpose of the "flush timer" in RIP?

Q3. In Dijkstra's algorithm, why do we always pick the unvisited node with the smallest distance next?

Q4. A network uses RIP. Router X has a route to subnet Y with hop count 14. Is this route usable? What if hop count reaches 15?

A1. OSPF uses triggered updates (LSAs flooded immediately) and each router has the full topology map, so it recalculates Dijkstra's instantly. RIP waits 30s between updates and must propagate changes hop-by-hop.

A2. The flush timer (240s) removes a route from the routing table entirely after it has been declared invalid (invalid timer = 180s). This frees memory and ensures stale routes don't persist.

A3. This is the greedy choice that guarantees optimality. Because all edge weights are non-negative, once a node is finalized with the smallest tentative distance, no future path can improve it — that distance is truly the shortest.

A4. Hop count 14 is usable (max is 15). At hop count 15, the route is still valid but barely. At 16 the route is considered unreachable (infinity) and is removed.

Q1 What algorithm does Distance Vector routing use to compute paths?

Distance Vector uses Bellman-Ford. Each router iteratively updates its distance estimates using neighbors' information. Dijkstra's is used by Link State (OSPF).

Q2 What is the maximum hop count in RIP before a destination is considered unreachable?

In RIP, hop count 16 = infinity (unreachable). The maximum usable hop count is 15. This limits RIP to small networks.

Q3 In two-node instability, why do routers 'count to infinity'?

A routing loop forms: each router thinks the other still has a valid path. They keep incrementing the hop count every exchange until reaching 16 (infinity).

Q4 Split Horizon prevents routing loops by:

Split Horizon: if router A learned about destination X from router B, A will not include X in updates sent back to B. This breaks two-node loops.

Q5 Why does Split Horizon fail to prevent three-node instability?

In 3-node loops (A→B→C→A), each router advertises back to a *different* neighbor, not the one they learned from. Split Horizon's rule doesn't apply across the three-way loop.

Q6 OSPF uses which algorithm to compute shortest paths?

OSPF uses Dijkstra's shortest path first (SPF) algorithm. Each router runs it locally after receiving all Link State Advertisements (LSAs) from the network.

Q7 In Dijkstra's algorithm, at each step we select:

Dijkstra's greedy strategy: always pick the unvisited node with the smallest tentative distance. This guarantees optimality when all edge weights are non-negative.

Q8 How does OSPF learn the full network topology?

Each OSPF router creates an LSA describing its links and floods it throughout the area. Every router collects all LSAs and builds an identical complete topology map.

Q9 The Bellman-Ford equation D_x(y) = min_v { cost(x,v) + D_v(y) } means:

The equation finds the best path to y by trying each neighbor v: go from x to v (cost(x,v)), then from v to y (D_v(y)). Pick the minimum over all neighbors v.

Q10 Which mechanism sends a routing update immediately upon detecting a topology change?

Triggered updates fire immediately when a route changes, rather than waiting for the next 30-second periodic cycle. This speeds convergence and reduces the window for counting-to-infinity.
